# RAW Viewer — 專案計劃書

> 狀態：v0.1 MVP 開發中｜最後更新：2026-10-01

## 1. 目標

做一個**免費、開源、輕快**的 RAW 瀏覽器，讓攝影師可以：

1. 快速逐張瀏覽一個資料夾內的 RAW 檔（上一張／下一張）
2. 自選兩張照片（A、B），把 A **半透明疊**在 B 上
3. 自行調整不透明度，直接看出兩張的差別（表情、焦點、構圖、動態）

### 為什麼要做

| 現有工具 | 缺點 |
|---|---|
| darktable / RawTherapee / digiKam | 能瀏覽、能並排，但不能半透明疊圖 |
| GIMP | 能疊圖層，但每次手動開檔，很慢 |
| nomacs | 靠「兩個視窗＋調視窗透明度」勉強做到，操作繁瑣，macOS 支援弱 |
| FastRawViewer / Photo Mechanic | 付費，且沒有疊圖比對 |

目前沒有一個工具同時做到「秒開 RAW」和「互動式半透明疊圖」。

## 2. 範圍

### 第一版要做（MVP）

- **格式：只支援 Sony ARW**
- 開啟資料夾，列出所有 `.ARW`
- 單張檢視，用 ← → 切換前後張，並預先載入前後幾張
- 底部縮圖列
- 只做 macOS（見 §3.2）
- **比對模式**
  - 使用者自選 A、B 兩張（預設為目前這張和下一張，可改成任意兩張）
  - A 疊在 B 上，用滑桿調整 A 的不透明度（0–100%）
  - 快捷鍵：數字鍵 `1`–`9`、`0` 快速切換 10%–100%
  - 兩張同步縮放和平移（適合位置相同的比對）
  - 可以單獨拖動 A 的位置（照片構圖不同時，自己手動對到想比的地方）
- 顯示基本 EXIF：快門、光圈、ISO、焦距、拍攝時間

### 第一版不做

- 自動對齊（不假設同一構圖）
- 修圖、調色、匯出
- Sony 以外的 RAW 格式
- 評分、標籤、刪除檔案（v2 再考慮）

## 3. 技術設計

### 3.1 RAW 讀取策略：預覽優先，且不經過系統 RAW 外掛

ARW 是 TIFF 結構：IFD0 放預覽 JPEG、方向、機型和 EXIF 指標，IFD1 放 160×120 縮圖，SubIFD 放 RAW 資料。

| 階段 | 來源 | 實測（M 系列 Mac） | 用途 |
|---|---|---|---|
| 縮圖 | 預覽 JPEG 縮小 | 毫秒級 | 縮圖列 |
| 一般瀏覽 | 自行解析 ARW 取出預覽 JPEG（1616×1080） | 12–32ms | 切換瀏覽、疊圖 |
| 完整解析度 | macOS ImageIO 解 RAW | 0.6–1.5 秒（每個機型首次另加約 5 秒，見 §6） | 停留 250ms 後在背景解碼並替換 |

> 實測樣本（raw.pixls.us）：α7 III（非壓縮）、α7 IV（無損壓縮）的內嵌預覽都是 1616×1080，所以完整解碼是必要的。
> ARW 內建的 160×120 縮圖上下有黑邊，縮圖列改用預覽縮小。

### 3.2 技術選型（已定案：Swift）

| 層 | 選擇 | 理由 |
|---|---|---|
| App | **Swift 5.10 + SwiftUI**，Swift Package 結構 | 原生、輕量；不需要 Xcode 專案檔，CLI 就能建置 |
| ARW 解析 | 自寫最小 TIFF 讀取器（`ARWReader`） | 繞過系統 RAW 外掛的首次延遲；全程邊界檢查，壞檔不會當掉 |
| 完整解碼 | ImageIO（系統 RawCamera） | 支援無損壓縮 ARW，不需第三方函式庫 |
| 疊圖 | SwiftUI 圖層 `.opacity`，由 GPU 合成 | 拖滑桿即時更新，不需自寫 shader |
| 互動 | AppKit `NSView` 接滑鼠、觸控板、滾輪 | SwiftUI 手勢拿不到滾輪和游標位置 |

放棄的方案：Tauri＋Rust 可跨平台，但需要自己找 RAW 解碼函式庫，第一版先求做好 macOS。

### 3.3 架構

```
Sources/
├── RawViewerCore/          # 無 UI，可單元測試
│   ├── PhotoScanner        # 掃資料夾、過濾 ARW（排除 ._ 中繼檔）、自然排序
│   ├── ARWReader           # 解析 TIFF：預覽 JPEG、方向、EXIF
│   ├── ImageLoader         # 預覽／縮圖／完整解碼；讀不到時退回 ImageIO
│   └── LRUCache
└── RawViewer/              # SwiftUI App
    ├── ImageStore          # 三層快取：縮圖 600／預覽 30／完整 4 張，背景載入
    ├── ViewerModel         # 目前張、A/B、不透明度、縮放平移、載入排程
    ├── ImageCanvas         # 疊圖顯示＋AppKit 互動層
    ├── ThumbnailStrip
    └── ContentView         # 工具列、比對控制列、快捷鍵
```

### 3.4 疊圖原理

```
輸出 = A × α + B × (1 − α)      α = 使用者設定的不透明度
```

兩張各自「符合視窗」後疊放；A 另有使用者拖動的位移；縮放和平移對兩者同步套用。

## 6. 風險與待確認

| 風險 | 狀態／對策 |
|---|---|
| macOS RawCamera 外掛在每個程序首次開某機型時卡約 5 秒（`sips` 也一樣） | 已繞過：預覽和 EXIF 自行解析；只有背景完整解碼會遇到 |
| 部分機型內嵌預覽太小 | 已實測為 1616×1080；完整解碼補上 |
| 其他 Sony 機型（APS-C、RX 系列、舊款 SR2/SRF）的 ARW 結構差異 | 解析失敗時自動退回 ImageIO；M5 補更多樣本 |
| 完整解析度圖約 100MB／張 | 完整解析度快取只留 4 張 |
| 測試用 RAW 樣本的版權 | 不放入 repo；用 raw.pixls.us 等授權明確的樣本，以環境變數指定 |
| 未簽章 App 會被 Gatekeeper 擋 | 目前本機 ad-hoc 簽章；發佈前需 Apple Developer 帳號 |
